# Protocol and integration contract

## MRDT wire compatibility

Vendor: `MissouriMRDT/RoveComm_CPP`, revision `bca1c255718804803615a4d9d435a12a2e2b6969`. See `vendor/mrdt/README.md` and preserved `LICENSE`/`SHA256SUMS`. Its actual `PackPacket<uint8_t>` and `UnpackData<uint8_t>` run in `native/rovecodec.cpp` through `comms/codec.py`.

| Field | Bytes | Value here |
| --- | --- | --- |
| Version | 1 | 3 |
| Data ID | 2, big endian | 60000, development envelope only |
| Element count | 2, big endian | payload byte length |
| Data type | 1 | 1 = UINT8 |
| Payload | count | authenticated canonical JSON |

Header length is **six bytes**. The wrapper accepts a maximum 8192-byte payload, rejects other IDs/types/versions and requires exact datagram length before native unpacking. It uses a generated enum-only compatibility header rather than importing an unlicensed board manifest. Tests assert known exact wire bytes and malformed-frame rejection. This verifies the selected UINT8 envelope codec; it does not verify stock firmware command IDs, hardware, or the complete upstream networking library.

## Application envelope v1

UTF-8 canonical JSON (sorted keys, compact separators, ASCII escapes, finite numbers) contains:

```json
{"v":1,"body":{"kind":"..."},"mac":"hex HMAC-SHA256 of canonical body"}
```

The decoder rejects duplicate keys, unknown top-level schema/fields, excessive nesting/array/string sizes and invalid authentication. Body limit: 7400 bytes; envelope limit: 7800. The shared simulation key is a random 32-byte file created locally with mode 0600 and never committed. The envelope authenticates integrity but is not encrypted and does not provide independent rover/drone credentials; each simulated peer is also pinned to a source UDP port. Field deployment requires a reviewed authenticated transport, separate peer keys and provisioning plan.

### Telemetry

Fields: `kind=telemetry`, `vehicle`, `boot_id`, increasing `seq`, `window`, `state`. C2 records receipt time locally and ignores reordered telemetry and retired boot IDs. Receipt freshness does not prove sensor sample age under network delay. The command window is a capability with a **receiver-local 1.25-second expiry**, generated by the vehicle and never interpreted as a remote timestamp.

State includes confirmed mode/mission, position, motion, synthetic indicator, package summaries, active package, local lease ID, route status, and relevant drone/rover reports. Drone state includes flight/landing-pad status, flight lock and the synthetic survey product. `synthetic=true` is required.

### Commands and ACKs

Commands contain `kind=command`, `vehicle`, `boot_id`, C2 `session`, unique `id`, increasing `seq`, echoed `window`, `action`, and `args`. ACKs contain `kind=ack`, the same vehicle/boot/session/ID, `status`, `reason`, and a state snapshot. C2 validates the matched endpoint as well as the IDs. ACK snapshots support transfer progress; dashboard mode comes from telemetry.

Lifecycle: `requested` → `accepted` → `completed`, or `rejected`; any missing confirmation can become `timeout`. Immediate operations return completed directly. Long-running route commands return accepted then a separate completion. STOP or session replacement rejects/cancels a pending route. A lost ACK never becomes success based on send return values, elapsed time or matching telemetry.

Initial requests have a 2.5-second acknowledgement deadline and at most four transmissions, spaced 0.3 seconds. Retransmissions use identical bytes and do not renew authority. Accepted route commands have a fixed 120-second completion deadline and at most 124 total transmissions, polling the cached result every second. The vehicle caches 256 results; a cached duplicate returns its prior result without side effects. If the result was evicted, its old window has expired and cannot cause repeat execution. Receiver route duration is bounded by 128 synthetic points at 0.25 seconds each.

Session `SYNC` stops prior motion on a changed session, retires the old session and establishes control sequencing. Actuation, mission and activation commands are strictly ordered. Package BEGIN/CHUNK/COMMIT and forwarded peer reports do not advance the control sequence: chunks have their own identity/index/integrity checks, and reports validate the originating peer's boot/sequence. This allows essential control to overtake independent bulk traffic without invalidating an otherwise resumable upload. All lanes retain session and receiver-window validation. A fresh STOP is exempt from ordinary sequence rejection but still requires matching boot/session and live window. It cannot bypass network loss or a dead vehicle; it is **not** the physical E-stop.

### Commands

| Action | Meaning |
| --- | --- |
| `SYNC` | Internal stopped-state reconciliation |
| `STOP` | Software motion stop; preserve physical E-stop distinction |
| `CLAIM_CONTROL` | Grant a local 0.8-second manual lease |
| `MANUAL` | Apply speed in [-1,1] with matching live lease; no renewal |
| `SET_MISSION` | Select delivery, assistance, route_finding or service while stopped/landed |
| `DRONE_STATE`, `ROVER_STATE` | Internal authenticated sequenced peer reports; do not refresh duplicates |
| `DRONE_TAKEOFF`, `DRONE_SURVEY`, `DRONE_LAND` | Simulated scouting/landing; no flight-controller API |
| `PACKAGE_BEGIN`, `PACKAGE_CHUNK`, `PACKAGE_COMMIT` | Metadata, bounded chunks, integrity/schema acceptance |
| `ACTIVATE_PACKAGE` | Explicitly select a validated package while stopped |
| `START_ROUTE` | Execute active synthetic route after landing/flight-lock guards |
| `RECOVER_ROUTE` | Simulated autonomous reverse traversal of visited route points |

## Route package v1

Exact fields:

```json
{"schema_version":1,"package_id":"survey-example-1","version":1,"crs":"EPSG:4326","units":"degrees","synthetic":true,"source":"simulated-drone","waypoints":[{"lat":38.4181,"lon":-110.777}]}
```

Coordinates are WGS 84 decimal degrees, separate named latitude/longitude fields. The example simulator accepts only a small demonstration box: latitude 38.410–38.426 and longitude -110.787–-110.767. These bounds are neither a competition geofence nor proof of navigable terrain. Unknown fields, real-data labels, other CRS/units, nonfinite values and >128 points are rejected.

BEGIN declares `{package_id,version,size,sha256,chunks}`. CHUNK declares `{package_id,index,data}` with strict base64 data and index bounds. COMMIT takes `{package_id}`. SHA-256 covers the entire canonical UTF-8 JSON; it detects corruption, not route safety. Duplicate identical BEGIN/CHUNK operations are resumable; conflicting duplicates are rejected. Reusing a validated package ID with changed content/version is rejected; use a new ID. Missing chunks prevent acceptance. Corrupt complete transfers are discarded. Activation is a separate command and requires a stopped rover. All package mutations are rejected while the rover moves.

## HTTP API

GET `/api/state` returns simulation status, vehicle snapshots/freshness, command history, events, transfers, fault profile/metrics and a session CSRF token. Mutations require same-origin JSON and `X-CSRF-Token`:

- POST `/api/command`: `{vehicle,action,args}`; returns the requested command record.
- POST `/api/transfer`: `{package}`; validates the review object and queues chunk transfer.
- POST `/api/faults`: complete desired fault settings; unspecified fields reset to defaults.

HTTP acceptance is only C2 queue admission. It never means the vehicle accepted or executed a command. API validation errors return 400, Host/Origin/CSRF violations 403, oversized input 413 and wrong media type 415.

Fault probabilities `loss`, `duplicate`, `reorder`, `ack_loss` range 0–1. `delay_ms` and `jitter_ms` range 0–3000. Booleans: `disconnect`, `telemetry_only`, `corrupt_bulk`. Delays are simulated scheduler timing, not measured real radio behavior. No current endpoint invokes physical hardware or changes the supervisor's process configuration.
